# Подключение внутреннего DNS и Zimbra

В примерах почтовый домен организации — `corp.example.test`, адрес портала — `ib.corp.example.test`, имя Zimbra — `mail.corp.example.test`. Замените эти значения на свои. Файлы настроек создаются на Docker-хосте в папке с `compose.yaml`.

## Внутренний DNS и HTTPS

1. Во внутренней DNS-зоне создайте запись **A** для `ib.corp.example.test`. Укажите внутренний IPv4-адрес сервера или HTTPS-прокси, например `192.168.10.20`.
2. Проверьте с рабочего компьютера, что имя разрешается во внутренний адрес. В PowerShell выполните `Resolve-DnsName ib.corp.example.test` со своим именем. Проверьте также имя существующей Zimbra.
3. Выпустите сертификат для имени портала в центре сертификации, которому доверяют рабочие компьютеры. Настройте внутренний HTTPS-прокси. Docker по умолчанию принимает веб-трафик на `127.0.0.1:8080` хоста. Прокси передаёт исходный заголовок `Host`. Пример для Nginx, запущенного на том же Linux-хосте:

   ```nginx
   server {
       listen 192.168.10.20:443 ssl;
       server_name ib.corp.example.test;
       ssl_certificate /etc/nginx/tls/ib-fullchain.pem;
       ssl_certificate_key /etc/nginx/tls/ib-key.pem;

       location / {
           proxy_set_header Host $http_host;
           proxy_pass http://127.0.0.1:8080;
       }
   }
   ```

4. Ограничьте доступ к HTTPS-порту корпоративными подсетями на межсетевом экране. Оставьте адрес портала во внутренней DNS-зоне. Приложение использует внутреннюю сеть Docker. Для шлюза почты разрешите на уровне сети только соединение с указанным внутренним адресом Zimbra и её портом SMTP.

## Служебный ящик Zimbra

1. В консоли администратора Zimbra создайте служебную учётную запись, например `training@corp.example.test`. Используйте обычный ящик отправителя с правом SMTP-аутентификации. Создайте или выделите один внутренний ящик для проверки.
2. Уточните существующий порт SMTP submission с STARTTLS. Обычно это TCP 587. Проверьте, что имя в сертификате Zimbra совпадает с именем SMTP, указанным в настройках. Для сертификата внутреннего центра сохраните PEM его цепочки.
3. Убедитесь, что Docker-хост может достичь SMTP-порта Zimbra. На Windows для предварительной проверки используйте `Test-NetConnection mail.corp.example.test -Port 587` со своим именем и портом. Успешный TCP-тест подтверждает связность. Отправка приглашения отдельно проверит STARTTLS и аутентификацию.

## Настройки Docker Compose

Создайте `.env` рядом с `compose.yaml`.

```dotenv
PORTAL_ORIGIN=https://ib.corp.example.test
PORTAL_DOMAIN=corp.example.test
PORTAL_SMTP_HOST=mail.corp.example.test
PORTAL_SMTP_IP=192.168.10.10
PORTAL_SMTP_PORT=587
```

`PORTAL_SMTP_IP` должен быть внутренним IPv4-адресом Zimbra из диапазонов RFC 1918. Используется один настроенный IP и порт. Внутри контейнера имя SMTP разрешается в адрес локального почтового шлюза, а сертификат проверяется по `PORTAL_SMTP_HOST`. Если адрес Zimbra изменится, обновите `.env` и пересоздайте контейнеры.

Создайте локальную папку `secrets`. В ней создайте `smtp.env`.

```dotenv
PORTAL_SMTP_USER=training@corp.example.test
PORTAL_SMTP_PASSWORD='пароль_служебного_ящика'
PORTAL_SMTP_CA=/run/portal-mail/zimbra-ca.pem
```

Подставьте реальный пароль. Поместите файл CA в `secrets/zimbra-ca.pem` и дайте контейнеру право читать этот PEM. Если сертификат выпущен общедоверенным центром, строку `PORTAL_SMTP_CA` можно опустить. Храните `smtp.env` на хосте с доступом только для администраторов Docker. В репозитории настроено игнорирование каталога `secrets` и файла `.env`.

Запустите портал с почтовым шлюзом после сборки или загрузки образа.

```powershell
docker compose -f compose.yaml -f mail.compose.yaml up -d --no-build --pull never --wait
```

Создайте администратора с адресом вашего домена.

```powershell
docker compose -f compose.yaml -f mail.compose.yaml exec app python manage.py admin admin@corp.example.test
```

## Контрольная отправка

1. Откройте портал по HTTPS под администратором. Добавьте внутреннего тестового сотрудника, указав адрес ящика проверки.
2. Создайте кампанию, назначьте сотруднику упражнение и в **Именном отчёте** нажмите **Отправить**. Проверьте адрес и нажмите **Отправить через Zimbra**.
3. Статус **Принято Zimbra** подтверждает приём сообщения SMTP-сервером. Откройте тестовый ящик и проверьте наличие письма **«Практика ИБ — учебное приглашение»**. При разборе доставки используйте Message-ID, который показывается при наведении на статус письма.
4. Войдите в портал под тестовым сотрудником, откройте упражнение и ответьте на вопрос. Вернитесь под администратором и обновите именной отчёт.

При статусе **Ошибка SMTP** проверьте адрес сервера, сертификат, пароль и ограничения служебного ящика. При статусе **Статус неизвестен** сначала сверьте Message-ID с журналом Zimbra. Сервер мог принять письмо до разрыва соединения.
