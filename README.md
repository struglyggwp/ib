# Практика ИБ

Локальный прототип админки для учебных кампаний. Встроенная демопочта позволяет пройти сценарий от письма до отчёта. Все участники и отправители вымышленные. В этой версии почтовый маршрут целиком проходит через демопочту. Для запуска достаточно Docker, подключение к Zimbra не требуется.

## Запуск на компьютере с Docker

Понадобятся Docker Engine с Compose v2 или Docker Desktop. Распакуйте архив, откройте терминал в папке проекта и выполните команды.

```sh
docker build --network=none -t praktika-ib-demo:1.0 .
docker compose up -d --no-build --pull never --wait
docker compose ps
```

Сборка использует официальный базовый образ Python. Если его ещё нет на компьютере, Docker скачает его из Docker Hub. Все файлы интерфейса уже в проекте, пакеты при сборке не скачиваются.

Админка доступна на компьютере с Docker по адресу [http://127.0.0.1:8080](http://127.0.0.1:8080).

## Запуск на сервере без интернета

На компьютере с доступом к Docker Hub соберите образ для той же архитектуры, что у целевого сервера, и выгрузите его.

```sh
docker build --network=none -t praktika-ib-demo:1.0 .
docker save -o praktika-ib-demo-1.0.tar praktika-ib-demo:1.0
```

Перенесите `praktika-ib-demo-1.0.tar` и `compose.yaml` на сервер. В папке с этими файлами выполните команды.

```sh
docker load -i praktika-ib-demo-1.0.tar
docker compose up -d --no-build --pull never --wait
docker compose ps
```

Архив образа содержит приложение и его среду выполнения. При загрузке и запуске Docker использует только локальные файлы.

## Доступ к стенду

По умолчанию HTTP-порт опубликован на `127.0.0.1`. Прикладной контейнер находится в отдельной внутренней сети Docker без выхода в интернет. Порт браузера обслуживает локальный шлюз, который передаёт запросы только приложению.

Если стенд запущен на отдельном сервере, можно открыть SSH-туннель с рабочей машины. Подставьте учётную запись и внутреннее имя сервера.

```sh
ssh -N -L 8080:127.0.0.1:8080 пользователь@внутренний-сервер
```

Оставьте туннель открытым и перейдите на [http://127.0.0.1:8080](http://127.0.0.1:8080) в браузере рабочей машины.

Для прямого доступа из тестового сегмента задайте в файле `.env` рядом с `compose.yaml` внутренний IPv4-адрес хоста Docker. Например, если серверу назначен `192.168.20.10`.

```dotenv
DEMO_BIND=192.168.20.10
DEMO_PORT=8080
```

Повторите `docker compose up -d --no-build --pull never --wait` и откройте `http://192.168.20.10:8080`. При необходимости создайте для этого адреса запись во внутреннем DNS. У демо общий доступ, поэтому ограничьте опубликованный порт тестовой подсетью на межсетевом экране. Для изоляции всего стенда сетевые правила хоста также должны запрещать внешний вход и выход.

## Проверка сценария

1. Нажмите **Новая кампания**. Укажите название и назначьте группам один или несколько учебных сценариев.
2. Нажмите **Открыть демопочту** в карточке кампании. Прототип выберет участника этой кампании. Откройте его письмо. В отчёте у участника появится время открытия.
3. Нажмите **Открыть учебную страницу**. Это создаст отметку о переходе.
4. Введите четыре цифры учебного кода с экрана. Как только код заполнен, появляется отметка о вводе. Сервер получает лишь идентификаторы кампании и вымышленного участника и тип события. Время добавляет сервер.
5. Вернитесь к отчёту кампании и найдите участника. У него будут три отметки с временем.

## Остановка и обновление

Команда ниже останавливает сервисы и сохраняет историю в томе Docker `praktika-ib-demo_practice-data`.

```sh
docker compose stop
```

Для обновления соберите или загрузите новую версию образа с тем же тегом, затем пересоздайте контейнеры. Тот же файл Compose подключит существующий том.

```sh
docker compose up -d --no-build --pull never --force-recreate --wait
```

Если страница недоступна, проверьте состояние контейнеров и их журналы.

```sh
docker compose ps
docker compose logs --tail=50 app web
```
