# Учебные материалы v0.19

Оба файла относятся к одному шаблону. В меню «Шаблоны» создайте шаблон и выберите HTML письма и HTML страницы. Поддерживаются документы UTF-8 до 2 МиБ каждый. Кнопка «Предпросмотр файлов» покажет оба материала и список удалённых элементов до записи в базу. После этого можно отредактировать содержимое и сохранить его. Повторная загрузка одного файла заменяет соответствующее поле.

Сохраняются текст, заголовки, списки, таблицы и встроенные PNG, JPEG и GIF. CSS, скрипты, внешние ресурсы, исходные ссылки и формы отбрасываются. Для вставки ссылки добавьте в текст письма метку `[[lesson]]`. По умолчанию кнопка перехода располагается в конце. На странице материала нет полей ввода.

В форме шаблона ссылки «Домены» и «Адреса отправителя» открывают справочники в админке. Добавьте корпоративный домен и адрес, вернитесь к шаблону и выберите отправителя. Используется общая административная учётная запись. Настройка DNS остаётся ручной.

## Запуск через Docker

Выполняйте команды из каталога `platform`. Для обновления существующей установки v0.18 используйте прежние значения .env, резервную копию PostgreSQL и прежнее имя Compose-проекта, чтобы подключить прежний том данных. На новой установке скопируйте .env.example в .env и замените DJANGO_SECRET_KEY, POSTGRES_PASSWORD и DJANGO_SUPERUSER_PASSWORD. Подготовьте образы и зависимости заранее, пока доступен реестр.

```sh
docker compose --profile mailtest build
docker compose --profile mailtest up -d
docker compose ps
```

Панель по умолчанию доступна по адресу http://127.0.0.1:8080, почта Mailpit по http://127.0.0.1:8025. Для размещения за внутренним HTTPS-прокси задайте внутренние адреса DJANGO_ALLOWED_HOSTS и DJANGO_CSRF_TRUSTED_ORIGINS. PORTAL_BIND_IP задаёт интерфейс на Docker-хосте. Ограничьте вход на него корпоративной подсетью. Не публикуйте этот хост в интернете.

## Подключение Zimbra

1. Создайте во внутреннем DNS запись для имени портала на внутренний HTTPS-прокси. Для SMTP используйте внутреннее имя Zimbra из её сертификата. Создание домена в панели не создаёт DNS-записи.
2. Подготовьте SMTP-учётку с правом отправки от нужных корпоративных адресов. Укажите SMTP_USERNAME, SMTP_PASSWORD и SMTP_FROM_EMAIL. Точные делегированные адреса перечислите через запятую в SMTP_APPROVED_ALIASES. Справочник в браузере допускает подготовку адресов до их подключения.
3. Укажите ZIMBRA_LAN_IP и ZIMBRA_TLS_NAME. Задайте SMTP_HOST равным ZIMBRA_TLS_NAME, SMTP_PORT=2587, SMTP_USE_STARTTLS=1 и SMTP_USE_SSL=0. Локальный шлюз направляет соединение на порт 587 заданного внутреннего IPv4. В случае внутреннего удостоверяющего центра подключите его PEM как read-only файл к web и worker и задайте SSL_CERT_FILE путём к этому файлу. Не отключайте проверку сертификата.
4. Укажите SIMULATION_PUBLIC_BASE_URL с внутренним HTTPS-адресом портала и его имя в SIMULATION_ALLOWED_LINK_HOSTS. Укажите тестовый ящик в SMTP_TEST_RECIPIENTS. Запустите `docker compose --profile zimbra up -d --build`. Web, worker и БД находятся во внутренней сети Docker. На межсетевом экране разрешите исходящий трафик сети SMTP-шлюза только к внутренней Zimbra на TCP 587.
5. Сохраните шаблон со статусом «Активный». Откройте «Предпросмотр», выберите тестовый ящик и нажмите «Отправить тестовое письмо». Проверьте во входящих адрес отправителя, HTML письма и переход на страницу. Черновик можно отправить для проверки вёрстки, его страница станет доступной при публикации.

Новые письма имеют маркировку корпоративного обучения и общую ссылку на материал. SMTP-отчёт фиксирует передачу писем серверу. Данные прежних кампаний и обработка прежних ссылок сохраняются. Перевод шаблона в архив закрывает общую страницу.
