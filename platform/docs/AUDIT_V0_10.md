# Технический аудит Security Awareness Platform v0.10

## Объём проверки

Проверены исходники Django, модели и миграции, views/forms/admin, шаблоны, настройки, Docker Compose, Dockerfile, entrypoint, Nginx и эксплуатационная/сетевая документация.

## Сильные стороны

- Слои приложения разделены на `core` и `campaigns`.
- PostgreSQL не опубликован на host-порты; веб-интерфейс опубликован только на loopback `127.0.0.1:8080`.
- Есть healthcheck для PostgreSQL и Redis, постоянные volumes и инструкции резервного копирования.
- Формы кампаний используют CSRF, страницы управления закрыты `login_required`.
- События не сохраняют значения полей учебных форм.

## Замечания и риски

1. `Django==5.1.7` закреплён на старой patch-версии. На дату аудита (2026-11-19) следует перейти на поддерживаемую LTS-ветку Django 5.2 и актуальный patch после проверки совместимости.
2. Автоматические тесты отсутствуют.
3. `record_safe_event` открыт для анонимных запросов и исключён из CSRF. Для публичного учебного endpoint это может быть оправдано, но нужны ограничение частоты, проверка origin/токена сценария и корректная модель дедупликации.
4. Дедупликационный ключ основан на campaign, kind и User-Agent. Один браузер фактически не может повторно зарегистрировать то же событие в той же кампании. На уровне БД нет уникального ограничения, поэтому конкурентные запросы могут создать дубли.
5. `/health/` публично сообщает состояние БД. Для локального прототипа риск ограничен, но лучше оставить минимальный liveness endpoint и вынести подробную диагностику в защищённый endpoint.
6. Контейнер приложения запускается от root. Для эксплуатации следует добавить непривилегированного пользователя.
7. Роли и аудит административных изменений отсутствуют.
8. В списке кампаний нет пагинации.
9. Redis/Celery подключены, но прикладных задач пока нет.
10. `djangorestframework` и `django-environ` установлены, но фактическое использование в коде не обнаружено.

## Реализовано в начальном объёме v0.11

- Приложение `employees`.
- Модели Department, Position, Employee.
- Каталог сотрудников: список, поиск, фильтр по подразделению и активности, карточка, создание и редактирование.
- CSV-импорт до 2 МБ, UTF-8/Windows-1251, разделители `,` и `;`, обязательные поля `first_name`, `last_name`, `email`.
- Автоматическое создание отсутствующих подразделений и должностей при импорте.
- Управление справочниками через Django Admin.
- Счётчик сотрудников на главной панели.
- Начальные автоматические тесты каталога.

## Ограничения проверки

В среде аудита Django не установлен, Docker CLI недоступен. Поэтому выполнена проверка синтаксиса Python (`compileall`), но миграции, Django system checks, тесты и сборка контейнеров не запускались. Перед использованием необходимо выполнить их в Docker-окружении проекта.
